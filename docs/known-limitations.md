# 已知限制

按「会遇到的人有多少」排序，每条都写了绕过办法。

## 1. SMIL 在 Chrome 已标记废弃

Chrome 从 2020 年起把 SMIL 标为 deprecated，但到 2026 年仍在正常执行，Chromium 团队也没有移除计划。
风险不在当前版本，而在"某天突然没了"。

**绕过**：改用 HTML 播放器（`exportHtml`），或把 `src/motion` 运行时接进自己的前端由 JS 驱动。
运行时本身不依赖 SMIL。

## 2. 导出是采样后线性插值

`exportSmil` 默认 30fps 采样，帧间由 SMIL 线性插值，而预览用的是缓动曲线的精确值。
两者差异随曲率变大而变大；`easeOutElastic` 这类高频摆动在 30fps 下会看出折线。

**绕过**：把 `fps` 提到 60（体积约翻倍）。导出面板里可直接改。

## 3. 起点对齐在超大段数下不是全局最优

闭环路径的起点/方向搜索是 O(n²)。段数 > 256 时改为按步长采样（`exhaustiveLimit`），
理论上可能错过更优的旋转量，表现为过渡中有一点点回旋。

**绕过**：`alignSubpaths(a, b, { exhaustiveLimit: 4096 })` 强制穷举（注意主线程耗时）。

## 4. 变换烘焙后不可再编辑

导出文件里没有 `transform` 动画，旋转/缩放在每一帧被写进了 `d`。
好处是不会塌陷、兼容性最好；代价是想在导出文件里单独调整 transform 就得重新导出。

**绕过**：保留 `.json` 工程（`timeline.toJSON()`），要改就回编辑器。

## 5. 只有 `<path>` 参与几何烘焙

`<rect>`、`<circle>`、`<polygon>` 不会被写上 `d` 动画。
上游的 `Pathformer` 能把它们转成 path，但本项目没有在绑定阶段自动调用（会改用户 DOM 结构）。

**绕过**：在 `markup` 里直接写 `<path>`，或导入前调 `new Pathformer(svg)`。

## 6. 非均匀缩放下 dash 长度是近似

`vector-effect: non-scaling-stroke` + 非等比缩放（`scaleX ≠ scaleY`）时，不存在一个标量能让 dash
同时匹配两个方向。运行时取 `sqrt(|det|)`，取的是几何平均。

**绕过**：避免对描边元素做非等比缩放；或改用导出文件（`pathLength` 归一化，跟随几何）。

## 7. 图标配对按索引，不理解语义

`normalizeIconPair` 按 `paths` 数组顺序配对。如果两个图标的路径顺序不一致（比如 A 的第一条是外框、
B 的第一条是细节），配对会看起来"错位"，虽然不会报错。

**绕过**：调整两个 icon 的 `paths` 顺序，让语义对齐。真正鲁棒的方案是按形状相似度做最优匹配，
那是另一套算法（匈牙利算法 + 形状特征），当前没有实现。

## 8. 中断只对单一轨道生效

`interrupt` 作用于一条轨道。如果一次状态切换需要同时改 3 条轨道（形状 + 描边 + 缩放），
需要调用 3 次；它们都在同一个时刻固化，视觉上仍然连续，但不保证三者共享同一条缓动曲线。

**绕过**：调用时传同一个 `at` 与相同的 `easing`。

## 9. 导出不压缩

`exportSmil` 输出的 `d` 列表保留 3 位小数，未做路径压缩（去重复点、合并共线）。
60fps + 多段轨道的文件会偏大（当前三个案例 6.8–34 KB）。

**绕过**：降低 `fps`；或导出后用 SVGO 处理（注意 `--disable` 掉会改写 `values` 的插件）。

## 10. 浏览器覆盖只验了 Chromium

端到端套件跑的是本机 Chrome。Firefox 的 SMIL 实现更完整（`d` 动画支持更早），
Safari 对 `pathLength` 与 `d` 的 SMIL 支持需要实测确认。

**绕过**：交付前在目标浏览器里打开 `demo/index.html` 目测；不支持就换 HTML 播放器。
