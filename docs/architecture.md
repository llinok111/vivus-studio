# 架构与取舍

## 1. 三层分工

```
Timeline   纯数据。sampleAt(t) 是总函数，无副作用。
Scene      唯一碰 DOM 的地方。绑定 data-motion、驱动 rAF、写 d / dashoffset / transform。
Exporter   只读 Timeline，不读 DOM（除了测量长度和轴心）。
```

导出器不读 DOM 状态，意味着导出文件不会带上编辑器私货（选中描边、悬停样式、临时分组）；
回放和导出都走同一个 `sampleAt`，意味着预览与导出不可能各说各话。

检查画面一致性时，回归脚本把两边栅格化成 40×40 墨迹掩码算 IoU，实测 0.990–1.000。

## 2. 为什么变形要经过「统一化」

播放和导出对几何的需求不一样：

- **播放**：任意时刻 t 只需要那一帧的形状，可以按需两两对齐（便宜）。
- **导出**：SMIL 要求一个 `values` 列表里所有 `d` 命令结构完全一致，否则整段动画被丢弃。

如果两处各用一套算法，中间帧的形状就会不一致——第一版就是这样，预览和导出差了 7% 的包围盒宽高比。
现在两边都走 `unifyMorphKeyframes`：按面积排序子路径 → 重采样到轨道内最大段数 → 逐帧相对前一帧
重定锚 → 去 `Z`。统一化结果按「关键帧签名」缓存，键帧一改就重建。

代价是播放时也要维护整条链（而不是只看相邻两帧），但缓存命中时采样只是一次字符串插值，实测无感。

## 3. 为什么变换要烘焙进几何

最初用 `animateTransform type="matrix"`。问题：SMIL 对矩阵做分量线性插值，旋转 180° 时
`a` 从 1 线性到 -1，中途 `|(a,b)| = 0.7`——形状一边转一边缩小。

改成对每个 `<path>` 采样 `d` 并应用仿射矩阵后：

- 旋转不塌陷；
- 包在 `<g>` 上的变换可以下推到每个子路径（`contains()` 判断祖先关系后复合矩阵）；
- 每个元素只剩一个动画，文件更小，兼容性更好；
- 代价：导出文件里的 transform 不可再单独编辑（已在限制里写明）。

轴心必须与预览一致。预览用的是 `bind()` 时的包围盒中心，所以导出时通过 `options.origins`
把 `scene.bindings[].origin` 传进去；不传才退回实时包围盒。

## 4. 中断的语义

「动画被打断」在实现上有三种常见做法，差别在**中断瞬间是否连续**：

| 做法 | 结果 |
|---|---|
| 直接改终点关键帧 | 形状瞬移到旧曲线在 t 时刻的值 → 视觉跳变 |
| 从头重播 | 节奏断裂 |
| **固化当前值再重定向**（本版） | 位置连续，速度可选连续 |

实现要点：

- `at` 之后**合成**关键帧全部作废（它们是作废未来的产物），否则反复中断会越积越多；
- 锚点用 `insertKeyframe`（不合并），因为锚点时刻的精度直接决定接缝；
- `preserveVelocity` 的衔接段用**线性**：缓动段的初速是 1.57×–2×，会造成"踢一下"。

回退验证：连续 5 次中断，最大接缝 Δ=0，关键帧 4 → 14。

## 5. dash 数学

`getTotalLength()` 返回用户单位长度，`stroke-dasharray` 也按用户单位解释。三个坑：

1. **`Math.ceil`**：向上取整最多多算 1 个单位，短路径末端会留一截永远画不完。用浮点。
2. **`non-scaling-stroke`**：dash 在渲染空间解析，用户单位长度不再描述覆盖整条路径所需的 dash。
   运行时用 `sqrt(|det(getScreenCTM())|)` 修正（均匀缩放精确，非均匀是合理近似；用包围盒比值
   会被旋转带偏）。导出用 `pathLength="1"` 彻底绕开单位问题。
3. **圆头端帽**：offset 恰好等于长度时，端帽仍会在起点留下一个点。导出把 offset 多推
   `strokeWidth / 2 / length`，并把 gap 从 1 改成 3，避免推开后下一个 dash 从尾部露出来。

## 6. 收敛策略（子路径 / 段数 / 起点）

| 不一致 | 处理 | 放弃的做法 |
|---|---|---|
| 子路径数量 | 按重心距离 + 面积差贪心配对；落单的塌缩到自身重心 | 直接丢弃（丢几何）、从头展开（形状从原点飞入） |
| 段数 | 反复拆分当前最长的段（de Casteljau 精确拆分） | 尾部补零长度段（留一段不响应的死区） |
| 起点 / 方向 | 闭环枚举旋转 × 2 个方向，取控制点距离平方和最小 | 固定起点（产生"麻花"扭转） |
| 闭合性 | 不一致时两边都设为开放 | 强行闭环（多出一条穿越线） |

段数 > 256 时旋转搜索改为步长采样，避免 O(n²) 卡住主线程。

## 7. 测试策略

| 层 | 工具 | 关注点 |
|---|---|---|
| 几何 | `node --test` | 圆弧径向误差 < 0.05%、拆分保形、端点精确、NaN 防护 |
| 时间轴 | `node --test` | 采样纯函数性、`hold` 阶梯、中断连续性、缓存不增长、JSON 往返 |
| 上游 | Karma（原样） | `src/vivus.js` 的 89 个行为契约 |
| 端到端 | 自研 CDP + PNG 解码 | 导出真的在动、缩放 4×、导出与预览 IoU、响应式无溢出 |

不引入 Playwright：整个端到端链路只用 Node 内置能力（`WebSocket`、`zlib`）加约 300 行 CDP 客户端，
依赖更少，CI 里也更快。

**像素断言而不是属性断言**：`getAttribute('d')` 返回的是基值，SMIL 播放时不会变，
只看属性会得出"动画没动"的错误结论。截图解码后比墨迹覆盖率与哈希，才是渲染器的真实状态。

## 8. 踩过的坑（会复发）

1. **给所有 path 都装 StrokePainter** → 只做变形的路径被打上 `dasharray`，进度停在 0，图形直接消失。
   现在画笔按需创建，只有 `number` 轨道才装。
2. **`sampleTrack` 在关键帧之外返回原始对象** → 变形轨道存 `{ d }`，渲染端要 `d` 字符串，
   于是过了最后一帧就不再写 DOM，图形冻结在当时的形态。已按轨道类型归一化。
3. **分离克隆上 `getBBox()` 返回全 0** → 导出时旋转轴心变成坐标系原点，形状转出画布。
   现在轴心来自启用元素，通过 `data-motion-origin` 带过去。
4. **`animateTransform` 与 `animate` 同元素** → 视觉上没问题，但矩阵插值会塌陷，已改为几何烘焙。
5. **`.stage` 的 `drop-shadow` 与网格** → 像素比对时被当成墨迹，IoU 从 0.99 掉到 0.49。
   深色背景的阈值要单独给（120 vs 60）。
6. **Windows 下 `node --test test/unit`** 会被当成模块路径解析失败，要写 glob：`"test/unit/*.test.js"`。
